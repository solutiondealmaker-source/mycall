# iClone — Deployment Guide

Stack: Next.js 16 + Convex + Convex Auth  
Runtime: Bun  
Infra: Docker + GHCR + VPS (Ubuntu 22.04+)

---

## GitHub Secrets required

Configure these in `Settings → Secrets and variables → Actions`:

| Secret | Description |
|--------|-------------|
| `CONVEX_DEPLOY_KEY` | Prod deploy key — Convex Dashboard → Settings → Deploy keys → Production |
| `NEXT_PUBLIC_CONVEX_URL` | Convex deployment URL (e.g. `https://acme-rabbit-123.convex.cloud`) |
| `NEXT_PUBLIC_CONVEX_SITE_URL` | Convex site URL — same deployment as above with the `.convex.site` suffix (e.g. `https://acme-rabbit-123.convex.site`). Used for the Google OAuth callback. |
| `GHCR_TOKEN` | GitHub PAT with scopes `write:packages` + `read:packages` + `delete:packages` (optional) |
| `SSH_HOST` | VPS IP address |
| `SSH_USER` | SSH user (`root` or a deploy user) |
| `SSH_PRIVATE_KEY` | Private SSH key (pair with the public key added to VPS `~/.ssh/authorized_keys`) |
| `SSH_KNOWN_HOSTS` | (optional but recommended) output of `ssh-keyscan <VPS_IP>` — prevents MITM |

> The `GHCR_TOKEN` must be a **Personal Access Token (classic)** — fine-grained tokens do not support `write:packages` at org level.

## VPS Setup (one-time)

### 1. Install Docker

```bash
# Ubuntu 22.04
apt update && apt upgrade -y
apt install -y docker.io docker-compose-plugin curl

# Enable and start Docker
systemctl enable --now docker
```

### 2. Create deploy directory

```bash
mkdir -p /srv/iclone
cd /srv/iclone
```

### 3. Copy docker-compose.yml

Copy the `docker-compose.yml` from the repo to `/srv/iclone/docker-compose.yml`.

```bash
# From your local machine:
scp docker-compose.yml root@<VPS_IP>:/srv/iclone/
```

### 4. Create .env.local

```bash
cp .env.example .env.local
# Edit with real production values
nano /srv/iclone/.env.local
chmod 600 /srv/iclone/.env.local
```

All server-side env vars go here (Google OAuth, Resend API key, etc.). Convex Auth keys (`JWT_PRIVATE_KEY`, `JWKS`) live on the Convex deployment, not in this file — they are generated by Convex on first deploy.  
`NEXT_PUBLIC_*` vars are baked at build time in CI — they do NOT need to be in `.env.local` at runtime.

### 5. Authenticate GHCR on VPS

```bash
echo "<YOUR_GHCR_TOKEN>" | docker login ghcr.io -u <github_username> --password-stdin
```

### 6. First deploy

```bash
cd /srv/iclone
docker compose pull
docker compose up -d
docker compose logs -f
```

## Reverse Proxy

### Option A — Caddy (recommended, auto-SSL)

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install caddy
```

`/etc/caddy/Caddyfile`:
```
iclone.yourdomain.com {
    reverse_proxy localhost:3000
}
```

```bash
systemctl reload caddy
```

### Option B — Coolify

1. Install Coolify on VPS: `curl -fsSL https://cdn.coollabs.io/coolify/install.sh | bash`
2. Add this repo as a source (GitHub)
3. Set build pack to Dockerfile
4. Add all env vars in Coolify UI (both public and secret)
5. Set domain + enable auto-SSL
6. Note: Coolify builds the image itself — the GHCR push from GHA is bypassed if you use Coolify's build pipeline. Choose one or the other.

### Option C — Nginx

```nginx
server {
    listen 80;
    server_name iclone.yourdomain.com;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl;
    server_name iclone.yourdomain.com;
    ssl_certificate /etc/letsencrypt/live/iclone.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/iclone.yourdomain.com/privkey.pem;
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Use `certbot --nginx` for Let's Encrypt SSL.

## DNS

Point an `A` record to your VPS IP:

```
iclone.yourdomain.com.  A  <VPS_IP>
```

SSL provisioning (Caddy or Certbot) requires DNS to have propagated.

## CI/CD Flow

```
git push main
     │
     ▼
[quality] ── biome check + tsc --noEmit + bun test
     │
     ▼
[convex] ── bunx convex deploy --prod --yes
     │
     ▼
[build-and-push] ── docker buildx + push ghcr.io/org/iclone:latest + :sha-XXXXXX
     │
     ▼
[deploy-vps]
  ├─ SSH pull new image
  ├─ docker compose up -d
  ├─ Wait healthcheck (30 × 5s = 150s max)
  └─ FAIL? → rollback to previous image SHA
```

## Rollback (manual)

List available image tags:
```bash
docker images ghcr.io/<org>/iclone
```

Pin to a specific SHA and restart:
```bash
# On VPS
cd /srv/iclone
docker compose down
# Edit docker-compose.yml: change image tag from :latest to :sha-XXXXXXX
docker compose up -d
```

Or re-run a previous successful GitHub Actions run from the Actions tab.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Container stuck `unhealthy` | App crashed at startup | `docker compose logs iclone-app` |
| 502 from reverse proxy | App not running on port 3000 | Check `docker ps` + `docker compose up -d` |
| `NEXT_PUBLIC_*` undefined client-side | Var not passed as build-arg | Check `NEXT_PUBLIC_CONVEX_URL` secret is set in GitHub |
| Convex functions not updated | Missing `--prod` flag | Re-run `[convex]` job or run deploy manually |
| `bun install --frozen-lockfile` fails | `bun.lock` out of sync | Run `bun install` locally, commit updated lock |
| SSL cert not provisioned | DNS not propagated or rate-limited | Wait 24h for DNS, check `caddy logs` or `certbot renew --dry-run` |
| Build OOM on VPS | VPS RAM too low | Add swap: `fallocate -l 2G /swapfile && mkswap /swapfile && swapon /swapfile` |
